# 0001 — 模型显示状态的文件赢家与同步交接

状态：已接受

## 背景

供应商顺序、模型顺序、供应商启停在浏览器存储中使用，在宿主 `ui-order.json` 中持久化，由 WebDAV 显式配置同步传递。存在几种分叉路径：

- WebDAV 已选出相同 `savedAt` 的文件赢家，浏览器却把不同的旧内容当作新编辑增加时间戳后回推。
- 拖动保存延迟 400 毫秒，立即同步时快照先于 POST 落盘；写入后又要等轮询或焦点变化才能采用。
- A→B→A 连续编辑的 POST 乱序到达；同内容的旧请求能降低文件时间戳，让中间旧请求随后胜出。
- 旧请求跨卸载或重启结束时，响应解析可以改写新世代状态，或未成功的保存身份会阻止重新落盘。

## 决策

1. GET 的文件时间戳大于或等于本地且有有效文档时，采用文件的全部显示状态；读取不是用户编辑，不因等时间戳内容不同生成新时间戳。当前正在编辑并排队保存时仍保护本地编辑。
2. `commitUiOrderGuarded` 对旧或等时间戳请求：不同内容拒绝，同内容幂等成功但不写文件，不降低时间戳；其它写入的时间戳也不低于当前值。保持原有部分字段更新、显式空数组清空及旧客户端无时间戳写入的兼容。
3. 追踪当前世代在途 POST，提供 `settleOrderSync()`。同页 WebDAV 请求快照前通过可选 `dsh-webdav-sync:before-snapshot` 等待实际保存完成，失败拒绝交接。原有 pagehide 的同步触发接口保留。
4. 成功写入配置后收到 `dsh-webdav-sync:applied`，等旧 GET 结束再立即重新拉取。通知不是编辑，不回推刚采用的内容。
5. 响应头到达以及 JSON 解析完成后都复验世代；旧409不能吞掉后来编辑。启动时清除旧在途追踪和乐观保存身份，由文件重新核验。交接循环也复验世代。
6. 不清理排序偏好中的旧 ID 来假装修复删除：排序函数只返回输入目录已存在的条目。宿主默认 patch watcher 和共享模型目录刷新已经存在，不增加重复重载或虚假设置事件。

## 影响

- 文件赢家、浏览器显示和手动同步快照对齐；乱序请求不再撤销最新顺序、模型排列或启停。
- 协议无需依赖 WebDAV 包，两插件仍可独立安装；只有同页面手动操作参与交接，其它标签页和后台定时同步仍使用原有保存与轮询机制。
- 时间戳仍是跨机器仲裁依据，不提供跨进程事务或校准设备时钟。WebDAV 文件不回退较新 `savedAt` 的既有规则不变。
- 补充等时间戳赢家、交接保存/失败、应用后持久化、旧409、卸载期间JSON、旧世代失败重试、服务端乱序时间戳回退回归；WebDAV 仓补充供应商/模型删除跨机器不复活测试。
- 本次只修源码和验证构建，不升版本、不发布、不改用户清单；实际运行环境需要加载两插件的修复产物才能生效。
