# 0003 — 生图模型只从宿主实时设置派生，文件只保存偏好与诊断

状态：已接受

## 背景

原生生图工具在插件加载时注册，模型列表则由另一条链路把 `llm-pi-ai` 的 `inputImageGen` 行同步进 `image.json`。工具执行、系统提示和配置页读取这份派生文件。启动或重载时宿主设置尚不可读，一次性同步会错过模型；随后设置事件或配置页 GET 才可能填充文件。同一会话因此能先报没有模型、稍后又正常生成，且不需要用户改变设置。

调用前补一次同步仍保留两份模型事实，也无法可靠区分暂时不可读与真实删空。将空对象或缺少 models 数组视为正在加载，会继续使用已被删除的旧连接。

核对宿主 `@deepseek-ai/dsh-settings@0.2.2-rc.1` 的公开实现后确认：`describe()` 仅返回运行中的设置条目，`value` 是完整已解析配置；空对象也是合法结果。读取时可能同步发出 `settings/document-updated`，所以事件不能充当唯一就绪信号，也不能在监听器里无保护地递归读取。

## 决策

- `src/image/state.ts` 的 `ImageConfiguration` 成为工具、命令、提示和配置路由共享的适配器。每次操作读取一份当前宿主 descriptor，纯派生模型列表，不依赖启动同步、定时重试、配置页访问、事件失效或上一次磁盘列表。
- descriptor 缺失、读取异常或结构无效明确返回配置不可用；合法空列表明确表示当前没有生图模型。真实移除模型立即生效，旧文件和上一次成功结果都不能授权生成。
- `src/index.ts` 对生图强制读取 fresh descriptor，并防护 `describe()` 同步事件带来的重入。其他功能可继续使用已有缓存，但不参与生图模型选择。
- `image.json` 新写入格式为 version 3，只保存 enabled、defaultModel、defaults、outputDir 和 observations。observations 用模型标识与连接指纹关联；文件内不再保存模型目录、URL、供应商配置或密钥引用。
- 旧 version 2 仅在内存迁移偏好和诊断；没有当前宿主模型时不能用旧行生成。只读操作不迁移写盘。第一次显式保存或调用诊断写入前，用排他创建保留原文到同目录 `.v2.bak`，再以唯一临时文件原子替换。损坏、不可读或未知版本的文件明确失败，不默默恢复默认并覆盖用户开关。
- 生图执行和命令解析固定使用同一份配置快照。异步请求期间的设置变化影响下一次操作，当前调用的诊断仍属于已捕获连接；同名模型更换地址或密钥引用后不继承旧连接诊断。
- `src/image/generate.ts` 必须显式注入配置，不再默认回退磁盘。停用开关在宿主设置不可用时仍优先拒绝生成。提示使用工具实际注册名，包括冲突时的 `dsh_image_generate`。
- 浏览器 GET 是只读实时投影。完成后的模型列表和失败结果不再以 30 秒 TTL 影响补全；仅合并同时在途读取。读取失败清除旧列表，过期响应不能覆盖保存后的新状态。宿主模型不可用时仍可显示已读取的偏好与工具注册状态以便调整开关。配置页按用户操作顺序串行提交偏好修改，避免不同字段的慢响应或同字段的连续操作倒序提交；卸载后的响应不再更新页面。

## 影响与迁移

用户无需重新选择默认模型或修改默认尺寸。默认选择在模型暂时移除时保留，模型恢复后可继续匹配；选择本身不会把模型重新加入目录。读取配置、获取提示、打开页面均不会创建或改写文件。生成完成和显式保存是仅有的正常写入来源。

version 3 不再支持手动把模型连接写入 image.json。应在宿主模型配置中标记生图；这确保工具、提示、命令和配置页使用同一来源。旧行的任意 params 覆盖不作为新的模型能力授权，连接匹配的 lastGoodParams 仅作为调用诊断继续使用。

这些保证覆盖配置生命周期一致性；宿主不可用、文件损坏、密钥失效和上游网络错误仍会明确报错，不能把外部故障保证为永不发生。

## 验证

`tests/image-state.spec.ts` 验证实时空值、无事件恢复、真实删除、文件故障、懒迁移、连接指纹和重载；`tests/image-host-routes.spec.ts` 用本地 HTTP 上游验证工具、提示、配置页和命令的一致行为、同步设置事件、工具名冲突、停用与单次快照。其余生成、超时、附件、补全和浏览器竞态测试覆盖现有入口。所有上游请求均由本地桩提供，不使用用户的付费生图接口。
