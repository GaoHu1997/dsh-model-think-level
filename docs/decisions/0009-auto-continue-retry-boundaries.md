# 0009 — 自动继续与供应商重试分层、限额与隐藏入口

状态：已接受

## 背景

DSH 的供应商请求重试由官方 `@deepseek-ai/dsh-llm-retry` 在同一轮请求内执行；插件的自动继续则在 `turn/end` 之后再次发送「继续」。两者都可能增加请求次数。若只显示自动继续次数，用户无法判断当前是在等待官方供应商重试，还是插件准备发起下一轮，也无法看出分页历史导致的请求计数只是下界。

同时，官方供应商配置中的 `retryPolicy` 是运行时能力的入口，而不是插件自动继续策略。插件需要保留官方执行器和已有配置数据，只隐藏容易造成双重配置误解的可见入口；不能通过改写请求或修改安装包来禁用官方重试。

## 决策

- 自动继续的 transient-error 等待采用以用户基准等待为起点的指数退避与有限抖动，本地退避封顶为基准等待与 120 秒两者的较大值，且不低于基准等待；合法的供应商 `Retry-After` 是不可截短的下限，即使超过本地上限也必须遵守。若等待将超出累计时限，则停止后续自动继续而不是提前发起请求。`max-tokens` 不做指数退避。
- 每条会话链增加自动继续次数、可见请求下界与累计时限三类预算。请求预算观察持久的 `llm/retry-started` 并按序号去重；官方重试只观察，不抢发「继续」，且耗尽自动继续预算时不伪装为已取消官方 RPC。旧宿主或分页不可见事件只能给出下界。
- UI 新增 `provider-retrying` 阶段，把官方等待、插件等待、已发送和预算耗尽分开表达；“停止自动继续”仅停止插件链，不承诺取消官方请求。预算耗尽显示具体是次数、请求数或时限。
- 新增少量可安全关闭的错误码选项，未知码仍不默认重试；永久错误保持关闭。配置数据保持向后兼容，旧记录使用默认值。
- 新增每会话有界 ledger：优先使用本运行器最新内存账本，持久化使用 localStorage 保存 24 小时内的序号、水位、预算、自动消息归属和 muted 状态，并限制最多 128 个会话。存储已有旧记录而后续写入失败时，同文档重绑不能回退预算或停止状态。已认领的待发回合、原始等待起点和退避参数只在本运行器内存中保留；连接 reset/绑定替换等待历史就绪后恢复原到期时间，不再次认领或累加失败次数，新的文档/标签页不从持久账本重放它。手动意图、排队消息、停止及禁用仍取消待发。写入失败时继续运行但不宣称跨页预算保证；无 ledger 的冷恢复不把历史中同文案「继续」认作插件回声，避免把手动意图吞掉。禁用期间不继续安排评估计时器。
- 手动操作改为「跳过本地等待」：可缩短本地基准/退避，但仍从原始等待起点遵守供应商 Retry-After 下限，且发送前继续检查次数、请求、时限及用户意图保护。
- `retryPolicy` 的官方入口仅在宿主供应商编辑/添加表单中做窄范围 DOM 隐藏：必须匹配 `customizedBody > details.customized > editor`、`rowCard/addCard`、`role=group` 的 `-retry-failure-label` ARIA 后缀、对应字段 label、`input/selectInput` select 以及完整 `''/normal/always` 选项，并排除插件根；只改 `display:none!important`，保存并恢复原 display 与 priority，底层 profile、值、事件和执行器不改。若宿主标记变化，隐藏适配失效而不会误伤其他设置。

## 影响

用户仍可通过官方运行时获得供应商级指数退避和 durable retry 事件，插件在其外层提供可解释、有限的自动继续链。两层预算不能阻断已经由官方发起的请求，且历史分页会使请求计数偏低；状态提示必须将这一限制告知用户。隐藏官方入口减少了配置分裂，但升级宿主后需要回归检查字段标签和表单标记。

## 验证

自动继续运行时、退避与两层状态的单元/集成测试覆盖退避、Retry-After、请求去重、官方重试识别、次数/请求/时限耗尽、控制器文案与键盘可访问性。恢复回归覆盖原到期时间的连接重置/绑定替换、等待历史加载、手动意图/排队/停止/禁用拦截、旧有效存储后续写失败时保留最新预算及 muted、跨新运行器不重放待发，以及手动跳过本地等待仍遵守供应商下限。官方字段隐藏覆盖精确匹配与 display 恢复，样式通过静态校验。未将此工作区安装到运行中的宿主，因此未做实时页面视觉验证；未修改插件版本、官方安装包或 profile。
